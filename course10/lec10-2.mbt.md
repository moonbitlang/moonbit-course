# 闭包 Closure

- 闭包：函数 + 它捕获的周边环境状态的引用
- 环境状态由词法作用域决定（代码结构决定，非运行时决定）

```moonbit
test {
  let mut i = 2
  fn debug_i() -> Int {
    i  // 捕获外层的 i
  }
  i = 3
  inspect(debug_i(), content="3")
  let i = 4 // 不同的 i
  inspect(debug_i(), content="3") // 不会被新的 i 影响
}
```

<!-- ssml
  什么是闭包呢？
  闭包是一个函数以及它所捆绑的周边环境状态的引用的组合。
  它的环境状态由词法环境决定。
  例如在下方的代码中，在第三行我们定义函数的时候，可以看到此处的 i 对应的是第二行的 i。
  因此，之后当我们使用 debug i 的时候，它所输出的都是第 2 行的 i 的值。
  我们在第 6 行进行修改，此时再次执行，输出也会进行对应的修改。
  而第 8 行，我们定义了另一个 i。虽然名称相同，但是与我们的闭包毫无关联，因此输出不会发生任何变化。
  闭包所捕获的环境与程序的结构对应，在代码定义的时候决定，而不是在运行时决定。
  <break time="500ms" />
-->

# 闭包的应用：数据封装

- 数据隐藏：外部无法直接访问内部变量
- 行为控制：可以添加校验逻辑
- 接口简洁：只暴露必要的操作

```moonbit
fn natural_number_get_and_set() -> (() -> Int, (Int) -> Unit) {
  let mut i = 0  // 私有变量
  fn get() -> Int {
    i
  }
  fn set(new_value : Int) -> Unit {
    if new_value >= 0 {
      i = new_value  // 只接受非负值
    }
  }
  (get, set)
}
```

<!-- ssml
  那么闭包有什么用呢？
  一种可能的用法是封装数据和行为。
  我们在一个函数中定义一个变量，这个变量的作用域就是这个函数，在其他地方的程序无法直接访问它。
  我们通过定义两个捕获了这个值的函数作为返回值来让使用者进行读写操作，如第 3 行、第 6 行所示。
  特别的，我们还可以在这些函数中加入对于数据的校验。
  如果我们直接将私有变量定义成一个结构体的可变字段，那么使用者可以为所欲为，而在这里，我们就可以过滤掉非法的输入。
  最后我们返回这两个函数。
  <break time="500ms" />
-->

# 闭包与抽象：Map 接口

- 使用闭包封装不同的哈希表实现
- 对使用者而言，实现细节不重要

```moonbit
struct Map[K, V] {
  get : (K) -> Option[V]
  put : (K, V) -> Unit
  remove : (K) -> Unit
  size : () -> Int
}
```

- 可以提供多个构造函数：
  - `Map::hash_open()` 开放寻址实现
  - `Map::hash_bucket()` 直接寻址实现

# Map 实现：开放寻址

```moonbit
fn[K : Hash + Eq, V] Map::hash_open() -> Map[K, V] {
  let map = HT_open_tombstone::make(8)

  {
    put: (k, v) => map.put(k, v),
    get: v => map.get(v),
    remove: k => map.remove(k),
    size: () => map.size,
  } // 返回包含闭包的结构体
}
```

- 匿名函数语法：`fn (<args>) { <body> }` 或 `(<args>) => { <body> }`
- 进一步省略圆括号和花括号：`arg => body`

# Map 扩展方法

```moonbit
fn[K, V] Map::is_empty(self : Map[K, V]) -> Bool {
  (self.size)() == 0
}

fn[K, V] Map::contains(self : Map[K, V], key : K) -> Bool {
  (self.get)(key) is Some(_)

```

- 基于基本操作实现更多便利方法

# 回顾：内部迭代器和外部迭代器

- 内部迭代器：
  - 调用者提供回调函数，迭代过程由迭代器自身来执行
  - 无法由调用者提前中止迭代
  - `int_iter.each(fn(elem) { f(elem) })`
- 外部迭代器：
  - 调用者主动从迭代器一个个拉取元素
  - 调用者可以随时停止来取元素来中止迭代
  - `while ext_iter.next() is Some(elem) { f(elem) }`

<!-- ssml
  接下来，我们介绍闭包的另一个应用，外部迭代器。
  我们之前学习过内部迭代器的概念，也对外部迭代器做过简短的介绍。
  让我们回顾一下。
  内部迭代器是指，调用者提供一个<phoneme alphabet="sapi" ph="hui 2 diao 4">回调</phoneme>函数，迭代过程由迭代器自身来执行。
  例如这里的 each 函数，它接收一个函数 f 作为参数，然后对列表中的每个元素调用这个函数。
  调用者只需要告诉迭代器"对每个元素做什么"，而不需要关心如何遍历列表。
  但是，内部迭代器有一个重要的局限性：调用者无法提前中止迭代。
  因为迭代器控制着整个遍历过程，调用者只能被动地接受每一个元素。
  即使我们不再需要更多元素，迭代仍会继续，直到处理完所有元素。
  为了解决这个问题，我们需要外部迭代器，让调用者来掌控迭代过程。
  <break time="500ms" />
-->

# 外部迭代器

- 核心思想：调用者主动从迭代器拉取元素
  - 调用者控制何时获取下一个元素
  - 可以随时停止迭代

```moonbit
// 外部迭代器的使用方式
while iter.next() is Some(elem) {
  // 处理元素
  if <某个条件> {
    break  // 可以随时停止！
  }
}
```

- 实现方法：使用闭包捕获迭代状态

<!-- ssml
  外部迭代器与内部迭代器相反，它允许调用者主动从迭代器中一个个拉取元素。
  调用者决定何时获取下一个元素，何时停止迭代。
  这种方式给了调用者完全的控制权。
  那么如何实现外部迭代器呢？
  关键是使用闭包来捕获和维护迭代状态。

# 外部迭代器：数据结构

- 本质上，外部迭代器 `Iterator[T]` 是一个函数：`() -> Option[T]`，通过 `iterator.next()` 调用
- 核心思想：
  - `next()`：每次调用返回下一个元素
  - 返回 `Some(value)` 表示还有元素
  - 返回 `None` 表示迭代结束
  - 函数内部通过闭包捕获迭代状态

<!-- ssml
  外部迭代器的核心是一个类型别名，它就是一个函数。
  这个函数每次调用时返回下一个元素，如果还有元素就返回 Some，如果没有了就返回 <lang xml:lang="en-US">None</lang>。
  这个函数会通过闭包捕获迭代器的内部状态，比如当前遍历到的位置。
  每次调用时，闭包会更新这个状态，然后返回相应的元素。
  <break time="500ms" />
-->

# 外部迭代器：列表

```moonbit
fn[T] List::iterator(self : List[T]) -> Iterator[T] {
  let mut current = self // 捕获可变状态
  fn next() -> Option[T] {
    match current {
      Nil => None
      Cons(head, tail) => {
        current = tail // 更新状态
        Some(head)
      }
    }
  }
  Iterator::new(next) // 生成迭代器
}
```

- 外部迭代器的构造函数：
  `fn[T] Iterator::new(next : () -> Option[T]) -> Iterator[T]`

<!-- ssml
  让我们看如何为列表创建外部迭代器。
  我们定义一个函数 <lang xml:lang="en-US">iterator</lang>，它返回一个迭代器对象。
  关键是第二行，我们定义了一个可变变量 current，初始值是整个列表。
  然后我们定义一个闭包 next。这个闭包会捕获 current。
  每次调用这个闭包时，我们检查 current 的值。
  如果是 <lang xml:lang="en-US">Nil</lang>，说明列表遍历完了，返回 <lang xml:lang="en-US">None</lang>。
  如果是 <lang xml:lang="en-US">Cons</lang>，我们取出头元素，将 current 更新为尾部列表，然后返回头元素。
  通过闭包，current 的状态在多次调用之间得以保持和更新。
  这就是外部迭代器的核心机制。
  <break time="500ms" />
-->

# 外部迭代器：使用示例

```moonbit
test {
  let list = Cons(1, Cons(2, Cons(3, Nil)))
  let iter = list.iterator()
  inspect(iter.next(), content="Some(1)")
  inspect(iter.next(), content="Some(2)")
  inspect(iter.next(), content="Some(3)")
  inspect(iter.next(), content="None")
  inspect(iter.next(), content="None")
  // or 
  while iter.next() is Some(v) {
    println(v)
  }
}
```

- 调用者完全控制迭代过程
- 可以在任何时候停止调用迭代器

<!-- ssml
  让我们看如何使用外部迭代器。
  我们创建一个列表，然后调用 <lang xml:lang="en-US">iterator</lang> 获得迭代器。
  之后，我们可以多次调用这个迭代器的 next 方法来获取元素。
  每次调用返回一个 <lang xml:lang="en-US">Option</lang>，包含下一个元素或表示结束的 <lang xml:lang="en-US">None</lang>。
  更重要的是，调用者可以在任何时候停止调用迭代器，从而提前结束迭代。
  例如，我们在调用两次 next 之后就停下来，也可以在取得 <lang xml:lang="en-US">None</lang> 之后继续调用，同样会获得 <lang xml:lang="en-US">None</lang>。
  这解决了内部迭代器无法提前停止的问题。
  一种经典的遍历外部迭代器的做法，是结合 while 循环和 is 表达式。
  在第 10 行，我们使用 while 循环来不停地调用 next 方法，对 Some 包含的元素进行处理，并在取得 <lang xml:lang="en-US">None</lang> 时退出循环。

# 转换迭代器

```moonbit
fn[T, R] Iterator::map(self : Iterator[T], f : (T) -> R) -> Iterator[R] {
  fn next() -> Option[R] {
    match self.next() {
      Some(value) => Some(f(value))
      None => None
    }
  }
  Iterator::new(next)
}

test {
  let list = Cons(1, Cons(2, Cons(3, Nil)))
  let iter = list.iterator().map(fn(x) { x * 2 })
  inspect(iter, content="[2, 4, 6]")
}
```

<!-- ssml
  和内部迭代器一样，外部迭代器也可以定义转换器。
  这里以 map 函数为例，它可以将迭代器的每个元素都进行对应的处理，得到新的迭代器。
  map 的实现很简单：我们定义一个新的 next 函数，它调用原迭代器，如果得到元素就应用转换函数 f，然后返回转换后的结果。
  这个新函数捕获了原迭代器 self 和转换函数 f。
  使用时，我们可以链式调用。
  例如这里我们将每个元素乘以 2。
  原列表 1、2、3，转换后就得到了 2、4、6.
  <break time="500ms" />
-->

# 无穷迭代器

```moonbit
fn naturals() -> Iterator[Int] {
  let mut n = 0
  fn next() -> Option[Int] {
    let current = n
    n = n + 1
    Some(current)
  }
  Iterator::new(next)
}
```

- 与 take 组合使用

```moonbit
test {
  let first_five = naturals().take(5)
  inspect(first_five, content="[0, 1, 2, 3, 4]")
}
```

<!-- ssml

  使用闭包，我们可以轻松创建无穷迭代器。

# 内部/外部迭代器对比

```moonbit
fn naturals_external() -> Iterator[Int] {
  let mut n = 0
  fn next() -> Option[Int] {
    let current = n
    n = n + 1
    Some(current)
  }
  Iterator::new(next)
}

let naturals_internal : Iter[Int] = Iter::new(fn(yield_) {
  fn go(n) {
    guard yield_(n) is IterContinue else { return IterEnd }
    go(n + 1)
  }
  go(0)
})
```

<!-- ssml
  最后，我们对比一下外部迭代器和内部迭代器在实现同样功能时的区别。
  代码片段中，分别用外部迭代器和内部迭代器实现了无穷的自然数迭代器。
  在外部迭代器中，我们无需关心调用者会如何使用这个迭代器。
  迭代过程是由调用者掌控的，迭代器只负责向外提供元素。
  相反，在内部迭代器中，迭代过程由迭代器自己掌控。
  迭代器捕获了访问元素的 yield 函数，在迭代器内部选择是否调用 yield，以及是否要继续迭代。
